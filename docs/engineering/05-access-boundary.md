# Slice 02c — Authority and bounded access
Previous exact head 11fd770ab223fb033360cb074530ffdcc927753a passed all push and PR checks (43645887412, 43645891918).
This slice adds a transport-independent server-side Access boundary. It is not a deployed HTTP API or a real identity-provider integration. The server supplies a verifier, a route and recorded time. The request contains no actor selection. Each call verifies its credential before parsing or accessing memory; a server-side verifier returns an already validated registry actor. The kernel still checks authorization in the locked DB transaction. A missing or invalid credential returns a common 401; verifier unavailability returns 503. Unauthorized and missing resources share a 404 shape. Explicit owner/scoped projections and acknowledgement shapes are constructed without serializing the kernel, raw events, SQL diagnostics, or full receipts to the recipient. COMMIT uncertainty is distinct and requires retry of the same command ID. No credentials or request payloads are intentionally logged here.

A deliberate design choice is to put this boundary adjacent to the existing storage crate pending actual web routing; no additional runtime service. serde_json is already pinned and in the existing lock; only a direct dependency edge is added. CI temporarily updates the lock using Cargo and records it for the next commit; final builds must be locked again. The real PostgreSQL integration test now also exercises the boundary with a test-only verifier and synthetic actors: authentication failure before parsing, provider outage, actor injection rejection, private-field omission, uniform denials, idempotent scoped retry, revocation recheck and sanitized storage failure.

Open gates: production OIDC/session verifier (signature, issuer, audience, expiry, revocation, account linking), reliable registry and membership transactions, TLS and HTTP limits/no-store/CSRF as applicable, response-side timing/error leakage and authentication revocation race policy, adversarial multi-tenant testing, deletion/retention, backup and restore, least privilege review, advisory/licensing audit. The synchronous store needs a bounded blocking boundary or async migration before an async HTTP server. The verifier is a trust port, not authentication by itself. Tests cannot prove real login or end-to-end tenant security. No real user or production data; no deployment or merge. New head CI pending.
