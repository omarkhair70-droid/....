# Slice 01 — World Language and Kernel
14 November 2026 · First implementation, not a prototype.

This branch adds a minimal Rust workspace with a validated inbound command contract and deterministic in-memory admission, revision transitions, snapshot-based sharing, independent principals' responses, revocation, owner and recipient projections, actor-scoped command idempotency, and trusted in-process replay. No external actions, database, identity provider, networking, interface, or intelligence engine yet.

## Decisions and limitations
- Rust 1.100.0 and two direct serde dependencies pinned; Cargo.lock is deliberately not hand-authored. First CI resolution is provisional until a generated and reviewed lockfile is committed. No claim of reproducibility until then.
- Typed parsing rejects duplicate and unknown field names, explicit null comment, excessive wire bytes, unsafe integer range, noncanonical IDs. Revisions must be integer JSON tokens; JSON Schema can also allow mathematically integral floating values, which the parser intentionally rejects. Unicode counts are scalar values. Shape tests use the original contract fixtures. The JSON Schema itself still needs independent Draft 2020-12 validator execution.
- Fixed verified principal registry supplied by trusted caller; no real user authentication, organizational roles or revocation of identity in this slice. The caller, not an untrusted client, supplies actor/time. Future identity events and durable replay must handle changing membership and erasure. Not a secure API by itself.
- Share IDs are unique per work; explicit excerpt is immutable, separate from private body. Recipients can respond multiple times to the same snapshot while authorized; each response is a separate record, not a commercial commitment. Owner may revise while recipient sees the original. No-op revision and repeated revocation with a new command ID are rejected. One accepted operation advances aggregate revision once.
- Trusted history and receipts are internal and contain private metadata or content; not transport projections or log output. Recipient projection intentionally omits current aggregate revision. The v0.1 internal expected_revision check may leak private activity if exposed directly to recipients: before G2 design a server-mediated reply against an opaque, scope-specific version and a transactional internal aggregate check; do not expose internal receipts/errors or current revision. Test timing/metadata side channels, tenant separation and revocation. No real privacy/security assurance until those gates.
- Current accepted record contains validated command, actor, timestamp and receipt; replay re-admits it with fixed registry and verifies revision/duplicate handling. No durable event envelope, independent schema evolution, tamper protection, deletion or transaction recovery yet. Define serialized event contract and privacy/retention policy before persistence. Never expose raw history to clients.
- All tests are synthetic; no real identities or communications. No local Rust toolchain available when authored. CI is configured with official checkout v4.2.2 immutable commit, verified against upstream tag. CI generates a provisional lock if absent, tests/lints, and checks formatting. Check results, fix issues and commit actual lock before G0/G1 sign-off. No benchmarks or completed gates claimed.
