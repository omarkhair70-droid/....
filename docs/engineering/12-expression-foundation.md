# Slice 04a — Semantic expression
Prior exact head 02b87dc0db6fd1bc23ce0d84b92cbe4aa9fed3c1 passed push 43648499332 and PR 43648504109. Based on research 03, design 01/05 and proposed design 06. This adds the first render-independent expression contract built from already authorized kernel views. No new dependency, no web application, no layout, no approved visual implementation.

Versioned JSON describes work or disclosure subject, title/body or scoped text, historical responses, and action preparation kinds. Owner actions bind the current aggregate revision; recipient reply binds only the disclosed snapshot. Revoked owner-visible disclosure retains history without a revoke action; recipient expression is available only after the existing access check. Share IDs are scoped to the known work route; response ordinal is local append-only identity, not a globally durable response ID. User-visible text, layout and effect execution are separate. Action descriptions are hints, not permission tokens or direct commands; existing authenticated and versioned command admission must still be enforced. No ability to edit/merge replies or create commitment. No source archives, raw history, full world or model output are passed into this projection.

Adds OwnerExpression and SharedExpression to the internal Access boundary, authenticated using the existing verifier port and actual memory reads. Old routes untouched. Pure tests exercise stable work identity, private change noninterference in the scoped value, immutable response history and action removal on revoke. PostgreSQL test extends authorization checks for expression access. Not an HTTP endpoint, UI runtime, general scene diff, real authentication, live communication, or a proof of privacy including timing; no real data or external calls. Independent JSON schema, stable semantic response IDs, explicit proposal projection, revalidation, layout IR and rendering remain future gates. New head must pass CI. No merge or deployment.
