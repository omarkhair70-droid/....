# الجولة البحثية الثانية — لغة العالم ومحرك التعبير
14 نوفمبر 2026. امتداد مباشر للجولة 02 ووثيقة المعمارية 05. مقترح بحثي هندسي؛ لا اختيار stack نهائي، ولا تصميم واجهة نهائي، ولا تنفيذ أو ادعاء جدة عالمية.

## 1. السؤال
كيف يتعامل الإنسان مباشرة مع شيء من العالم، بينما يستطيع الحاسوب فهم معنى الفعل، والتحقق من صلاحيته، وحساب أثره، والتعبير عنه دون تغيير هوية الشيء؟ لا نريد واجهة ترسم كل المعرفة ولا لغة برمجة يتعلمها المستخدم. نريد معنى واحدًا قابلًا لتعبيرات مختلفة وفق السياق والصلاحية. نميز اللغة الداخلية التي يفهمها المحرك عن اللغة الطبيعية والعلامات المرئية والأفعال البشرية.

## 3. الاختراع المقترح: سلسلة ترجمة دلالية قابلة للتحقق
لا نريد كتابة HTML لكل حالة ولا توليد واجهة عشوائية عبر LLM. نقترح تمثيلات وسيطة ذات أنواع:
- World IR: المعنى والحالة المأذون بها؛ هويات دائمة، حقائق وادعاءات وافتراضات، أعمال، إرادات، علاقات، مشاركة، زمن.
- Expression IR: الشيء الذي يعبر عن جزء مأذون من العالم: subject id، semantic role، content، actions، dependencies، order، revision، disclosure rules. لا HTML حر ولا شيفرة من النموذج.
- Layout IR: قيود قابلة للقياس حول القراءة والمساحة والأولوية والاستمرارية؛ لا معنى تجاريًا إضافيًا ولا حقًا جديدًا في الوصول.
- Render plan: عناصر DOM/SVG أو طبقات رسم اختيارية، مربوطة بهوية دلالية. GPU لا يقبل أسرارًا أو جزءًا غير مصرح من العالم. كل عنصر قابل للتفاعل له مسار keyboard وaccessible name/action، وتبقى الوظائف عند تعطيل الرسم الاختياري.

لا يتحول هذا إلى أربع لغات نصية أو أربع خدمات. الأول عقد النواة؛ الثاني والثالث والرابع طبقات من محرك التعبير. قد تكفي أنواع Rust/TypeScript وversioned JSON اليوم؛ نحو خاص فقط إن ظهرت حاجة تأليف قواعد وتحققها.

## 4. رياضيات الإسقاط والعودة
لتكن W_r الحالة عند مراجعة r، وa الفاعل، وc سياق التركيز، وd إعدادات الجهاز والإتاحة، وpi_a إسقاطًا مأذونًا يُصدر على الخادم. عندئذ:
V = E(pi_a(W_r), c)
L = Layout(V, d, L_prev)
Frame = Render(L, V)
لا يجوز لـ E أو Layout أو Render الوصول إلى W الكامل. لا يتغير معنى العمل باختلاف حجم الشاشة أو renderer.

التفاعل u ليس كتابة مباشرة في W:
Intent = Interpret(u, V, r)
Proposal = ValidateIntent(Intent, allowed_actions, schema)
Command = Resolve(Proposal, actor, exact target/version, explicit confirmation if needed)
إن قُبل الأمر داخل النواة: W_(r+1) = T(W_r, Event). قد يكون الفعل تحديثًا محليًا للتركيز فقط دون حدث تجاري. وقد يُرفض أو يتطلب توضيحًا عند عدم إمكان تعيين المعنى من التفاعل. لا يعيد المحرك تفسير النقر على اقتراح تعاون بوصفه قبولًا. لا تتحول الحركة البصرية إلى التزام.

قوانين مستلهمة من bidirectional transformations، وليست ادعاء أن كل العمليات lenses رياضية:
- تعديل صفر: لا أثر تجاريًا.
- تعديل مسموح محدد: بعد قبول الأمر يعكس العرض المعنى الجديد الصحيح، لا مجرد صدى نية المستخدم.
- ما لم يتأثر بالعملية يبقى ثابت الهوية والمحتوى؛ التغيير المشتق المبرر يتحدث فقط في نطاقه.
- مبهم/غير مأذون: يُرفض أو يُطلب تفسير؛ لا تخمين لقرار ملزم.
- ثبات السلطة: إعادة ترتيب العرض أو تصغيره أو تبديل محرك الرسم لا تمنح إذنًا جديدًا.
- شروط عدم تسرب: إذا تطابقت الحالة المأذون بها والإعدادات والسياق، لا ينتج من اختلاف حقول سرية تغيير مرئي أو اقتراح أو metadata في تلك الجلسة. التوقيت والتخزين المؤقت وأخطاء الوصول تحتاج اختبارًا منفصلًا؛ ليست مضمونة بهذه المعادلة وحدها.

## 5. رياضيات التكوين المرئي
بعد تحديد ترتيب دلالي مقروء مسبقًا، ندرس مسألة تحسين اختيارية على المواقع والأحجام x:
min J(x) = alpha*movement(x,x_prev) + beta*reading_penalty(x) + gamma*overlap_penalty(x) + delta*salience_mismatch(x).
Subject to hard constraints: minimum readable area, non-overlap of actionable text, viewport bounds where applicable, visible focus, correct RTL/LTR reading order, and access-safe content.
الأوزان لم تحدد؛ ليست معادلة ثابتة للجمال. المقادير يجب تطبيعها واختبارها، والقيود الدلالية والإتاحة صلبة لا يجوز التضحية بها عند تقليل J. CSS Grid/Flex/flow هي المرجع الأول؛ Cassowary/linear constraints فقط عند ظهور عجز في تركيب حقيقي. عند تعذر حل التكوين، نعود إلى ترتيب دلالي واضح وقابل للتمرير؛ لا نخفي المحتوى ولا نوقف الوظيفة. easing/springs اختيارية مع وصول نهائي ثابت، وreduced motion يلغي انتقالات غير ضرورية. الوضع البصري لا يغير الواقع.

## 6. مثال واحد على المعنى (خيالي للاختبار، ليس تصميمًا بصريًا ولا بيانات إنتاج)
عمل مع شريك: تجربة تشغيل في ستة مواقع. المؤسس يغيّر العدد إلى اثنين في التعبير الذي يرى فيه العمل. ينشأ ReviseAssumption يخص نطاق العمل المحدد. النواة تقبل وفق صلاحية الفاعل والنسخة. تتأثر تقديرات الموارد المعتمدة على العدد، وتتوقف المشتقات التي لا تزال تستعمل ستة. لا يتغير اسم العمل أو رد الشريك السابق. إذا كانت موافقته مرتبطة بستة مواقع، تظهر باعتبارها موافقة على الإصدار السابق، لا الجديد؛ نسخة مشاركة جديدة تحتاج إذنًا وردًا جديدًا. لا يعد التعديل بإرسال شيء.
طرف ثان يدخل من دعوة؛ يرى نطاقه فقط. قد يبدأ حوارًا دون عمل مشترك أصلًا. عند إلغاء إذنه، لا يعتمد النظام على اختفاء العنصر بصريًا؛ يمنع الوصول على الخادم ويلغي التحديثات والتضمينات المشتقة ويحذف النسخ المؤقتة حسب السياسة. لا يمكن ضمان استرداد نسخة سبق للطرف رؤيتها.

## 7. قرار مرشح لكل طبقة (لم يختبر)
- نبتكر: World IR وأنواع الفعل والمعنى، إسقاطات مرتبطة بالصلاحيات، ربط التعبير بالفعل، سياسة حفظ السياق، ربط تغيير الواقع بالمشتقات والتعبير؛ لا نبتكر compiler عام ولا renderer من الصفر.
- مرشح افتراضي: JSON schemas + Rust types للنواة، TypeScript typed adapters؛ React أو DOM runtime بحسب قياس التحديث والفوكس؛ CSS Grid/Flex، SVG، View Transitions عند الدعم، DOM-first.
- مرشح مشروط: Cassowary/kiwi-like solver، Vega للمعلومات التي تستحق رسمًا، CanvasKit/Rive للرسوم المتخصصة، WebGPU/WGSL للحساب أو الرسم الذي يثبت أنه يحتاجها. لا ندمج خمس مكتبات رسم لمجرد التنوع.
- مؤجل: syntax textual DSL، language workbench، MLIR integration، GPU-first engine، generative UI arbitrary code. تدوين الأسباب والقياسات قبل أي إضافة.
- التوافق العربي: shaping وbidi وline breaking وتحرير IME وتحديد النص عند التكبير، أحجام قراءة وأماكن focus. لا نرسم نص التحكم على canvas وحده. لا نفترض نجاح التشكيل أو الإتاحة قبل القياس.

## 8. خطة تحقق هندسية مرتبطة بالمنتج الواحد
1. contract tests: نفس الفعل (كيبورد/لمس/فأرة) إلى نية دلالية واحدة؛ رفض stale revision وambiguous update وunauthorized command؛ الحفاظ على authored fields.
2. مقارنة تسوية كاملة وتزايدية لنفس المعنى: نتائج متساوية تحت نفس المدخلات، وتغير subset فقط. قياس p50/p95، allocations، max lag وأثر تغييرات متتابعة.
3. مقارنة DOM/CSS baseline مع constraint layout حين يوجد تركيب لا تسعه الطرق القياسية؛ responsive 320/768/1440px، تكبير 200%، Arabic+English mixed text، keyboard، screen reader، reduced motion، focus restore. لا ضرورة لتجهيز واجهتين للمستخدم؛ اختبارات المحرك على نفس contract.
4. GPU/SVG/DOM conditional rendering: إن تحددت حالة رسوم/حساب مؤثرة، قياس frame time, startup bundle, memory, low-power device, GPU loss fallback. لا أهداف أداء مصطنعة قبل تحديد hardware وworkload. أهداف وثيقة 05 ما زالت targets لا measurements.
5. cross-scope tests: اختلاف البيانات الخاصة لا يؤثر على تمثيل طرف غير مأذون؛ عدم تسرب عبر error/metadata/cache/telemetry؛ revocation وout-of-order updates؛ موافقة B على revision سابق لا تنتقل تلقائيًا.
6. تقييم إنساني: هل الشخص يتعامل مع الشيء نفسه لا أسماء المحركات؟ هل يفهم ما تغير ولماذا وما يمكنه فعله؟ هل يستعيد ما كان يعمل عليه؟ لا نقيس الجمال بعدد الحركة أو العناصر.

## 9. المخرج
أصبح لدينا تصور أدق لاختراع لغة العالم دون كتابة لغة أو محرك رسومي عام لمجرد الجدة. ما يميز البحث هو العقد بين معنى العالم والتعبير وفعل إنسان مستقل. يجب دراسة prior art في أنظمة collaborative semantics وbidirectional UI قبل أي ادعاء أصالة. الجولات التالية تتناول الاستدلال بالمصادر وعدم اليقين والتخطيط متعدد الأطراف وتصميم عقد التنفيذ الخارجي، ثم نجمع مصفوفة قرار واحدة للـStack مع الحدود والاختبارات والتكلفة. لا نكرر التفكير إلى ما لا نهاية؛ كل جولة تحل سؤالًا محددًا وتضيق الاختيارات. لا كود أو اعتماد تبعية أو نشر في هذه الجولة.
